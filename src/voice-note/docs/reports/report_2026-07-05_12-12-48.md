# voice-note Tab Navigation Runtime Key Intercept

## Summary

Adjusted tab navigation to intercept `h`/`l` and arrow-key presses at the app
event level so tab switching does not compete with widget-level key handling.

## Changes

- Added `on_key()` handling for `h`, `l`, `left`, and `right`.
- Stopped propagation and default handling for those keys after switching tabs.
- Kept the wrap-around tab cycle introduced earlier.
- Added a direct event-level test to verify that a key press updates the active
  tab and is consumed.

## Checks Run

- `PYTHONPATH=src/voice-note uv run python -m unittest discover -s src/voice-note/tests`

## Notes

- This patch is specifically about the runtime event path, which is what caused
  the “it still jumps weirdly” behavior. The key bindings alone were not
  sufficient in the live TUI.
