# Report: Unix-Style Tool Convention Update

## Summary

Clarified the repository's shared tool contract so new tools follow explicit
Unix-style I/O and flag-priority rules.

## Files Changed

- `docs/guidelines/ARCHITECTURE_GUIDELINE.md`
- `docs/roles/TOOL_ENGINEER.md`
- `docs/improvements_plan.md`
- `docs/reports/report_2026-07-11_22-21-28.md`

## Changes Made

- Defined explicit I/O priority:
  - `--input` overrides `stdin`
  - `--output` overrides `stdout`
  - `--logs` or `--log-file` adds persistent logs without replacing `stderr`
- Added the common default flag set for new tools.
- Mirrored the same rules in the `TOOL_ENGINEER` role so the implementation
  guidance is easy to find.
- Marked the documentation improvement plan as updated for the I/O convention
  and report-tracking rules.

## Checks Performed

- Reviewed the current architecture and role docs before editing.
- Verified the wording stays aligned with the existing CLI-first/tool-wrapper
  structure.
- Confirmed the updated files read cleanly after patching.

## Remaining Risks

- Existing module READMEs may still vary in how they describe flags and I/O.
- `src/dictate/docs/ARCHITECTURE.md` still may need a follow-up mirror of these
  rules if that doc is meant to stay fully synchronized.
